# Photo compressor

Массовое сжатие JPEG для фотоархива на PHP. Запускается через Docker Compose:
PHP на компьютере устанавливать не нужно. Для Linux, macOS и Windows нужен
работающий Docker с поддержкой Linux-контейнеров и Docker Compose v2+.

## Быстрый запуск

Команды выполняются из корня проекта. Положите фотографии в `input/`.

```sh
docker compose build
docker compose run --rm compressor
```

Скрипт обработает все `.jpg` и `.jpeg` в `input/` (без учёта регистра),
сохранит результат в `output/` и завершится. Вложенные папки не обходятся.
Исходники подключены к контейнеру только для чтения.

```text
input/IMG_0001.JPG
output/2024/2024-06-15/IMG_0001.JPG
```

Повторный запуск пропускает существующие результаты. При необходимости
явно разрешите их замену:

```sh
docker compose run --rm compressor --overwrite
```

## Запуск и остановка контейнера

Это пакетная утилита: контейнер работает до окончания обработки, затем выходит.
Вариант запуска через Compose с возвратом кода завершения скрипта:

```sh
docker compose up --build --abort-on-container-exit --exit-code-from compressor
```

Запуск в фоне, просмотр журнала и остановка:

```sh
docker compose up -d
docker compose logs -f compressor
docker compose stop compressor
docker compose down
```

При запуске в терминале обработку можно прервать `Ctrl+C`.
Для одноразового контейнера, запущенного через `run`, из другого терминала:

```sh
docker compose ps --all --orphans
docker stop <имя-или-ID-контейнера>
```

`run --rm` удаляет завершившийся контейнер. `down` удаляет контейнеры сервиса
и сеть; файлы в `input/` и `output/` остаются на диске.
После принудительного прерывания во время записи может остаться скрытый
файл `.photo-*`; после остановки обработки его можно удалить.
Файл `.compressor.lock` удалять не нужно: блокировка освобождается при выходе процесса.

## Тестовый прогон

В `tests/fixtures/` включены два синтетических JPEG с текстурой, градиентами
и EXIF. Они предназначены для проверки алгоритма, а не для оценки качества
реальных фотографий.

```sh
docker compose run --rm compressor --input /app/tests/fixtures --output /app/output/demo
```

Ожидаемый результат:

| Файл | Исходные пиксели | EXIF Orientation | Результат внутри `output/demo/` |
| --- | --- | --- | --- |
| `landscape.jpg` | 3200×1800 | 1 | `2024/2024-06-15/landscape.jpg`, 1920×1080 |
| `portrait-exif.jpg` | 3000×2000 | 6 | `2024/2024-12-03/portrait-exif.jpg`, 1080×1620 |

Оба изображения можно просмотреть обычным просмотрщиком. Второе содержит
поворот в EXIF, поэтому просмотрщик может сразу показать его вертикально.

Пересоздать отсутствующие изображения на компьютере (существующие пропускаются),
затем включить их в образ:

```sh
docker compose run --rm --volume ./tests/fixtures:/fixtures --entrypoint php compressor /app/scripts/generate-fixtures.php /fixtures
docker compose build
```

Автоматическая проверка без изменения ваших `input/` и `output/`:

```sh
docker compose run --rm --entrypoint php compressor /app/tests/run.php
```

Проверяются размеры, все восемь ориентаций EXIF по цветам углов, даты,
копирование маленьких файлов, повторный запуск, перезапись, повреждённый JPEG,
права записи, блокировка параллельного запуска, ограничение памяти, имена файлов
с пробелами и Unicode, входные и выходные симлинки, а также вывод `--help`.
Временные файлы тестов создаются внутри контейнера и удаляются после проверки.

## Параметры обработки

```sh
docker compose run --rm compressor --quality 80 --coefficient 0.75 --timezone Europe/Bratislava
docker compose run --rm compressor --width 2560 --height 1440
docker compose run --rm compressor --help
```

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `--input` | `/app/input` | Папка исходников внутри контейнера |
| `--output` | `/app/output` | Корень архива внутри контейнера |
| `--width` | `1920` | Большая сторона рамки, целое 1–10000 |
| `--height` | `1080` | Малая сторона рамки, целое 1–10000 |
| `--coefficient` | `1` | Множитель обеих сторон, больше 0 и не больше 10 |
| `--quality` | `85` | Качество JPEG, целое 1–100; при прямом копировании не применяется |
| `--timezone` | `UTC` | Часовой пояс для EXIF без зоны и даты файлов |
| `--overwrite` | выключен | Заменять существующие файлы результата |

Поддерживаются формы `--quality 80` и `--quality=80`.
Пути в параметрах относятся к файловой системе контейнера. Для других папок
на компьютере переопределите bind mounts в `compose.yaml` или добавьте тома:

```sh
docker compose run --rm --volume /absolute/path/photos:/photos:ro --volume /absolute/path/archive:/archive compressor --input /photos --output /archive
```

На Windows используйте существующие абсолютные пути Docker Desktop, например
`"C:/Photos:/photos:ro"` и `"D:/Archive:/archive"`.

На Linux контейнер по умолчанию работает с UID/GID `1000:1000`. Если у вашего
пользователя другие значения, передайте их при запуске:

```sh
LOCAL_UID=$(id -u) LOCAL_GID=$(id -g) docker compose run --rm compressor
```

Также можно записать `LOCAL_UID=...`, `LOCAL_GID=...` и `PHP_MEMORY_LIMIT=512M`
в локальный `.env` рядом с `compose.yaml`. Папка результата должна быть доступна
этому пользователю для записи.

Для крупных фотографий можно увеличить лимит PHP (если на компьютере хватает памяти):

```sh
docker compose run --rm -e PHP_MEMORY_LIMIT=1G compressor
```

Лимит по умолчанию — 512 МБ. Перед декодированием оценивается необходимая
память; оценка приблизительная, это не ограничение памяти всего контейнера.

## Алгоритм и ограничения

Общая логика исходного `run.php` сохранена:

1. Взять дату `DateTimeOriginal` из EXIF; при отсутствии или неверной дате —
   время изменения исходного файла. Часовой пояс по умолчанию задан явно: UTC.
2. Применить поворот/отражение EXIF к пикселям.
3. Вписать горизонтальный снимок в 1920×1080, вертикальный — в 1080×1920,
   квадратный — в 1920×1920. Умножить рамку на коэффициент.
   Пропорции сохраняются, обрезки и увеличения нет.
4. Маленький снимок без необходимого поворота/отражения скопировать побайтно.
   Остальные пересохранить JPEG с качеством 85.
5. Сохранить в `output/ГОД/ГОД-МЕСЯЦ-ДЕНЬ/исходное-имя.jpg`.

Сжатие с потерями. При пересохранении GD удаляет EXIF, GPS, IPTC и ICC-профиль;
цвета фотографий с нестандартным профилем могут измениться. Дата съёмки
остаётся в пути и времени изменения результата. Побайтовая копия сохраняет
все метаданные. Результат иногда может оказаться больше оригинала — это
зависит от содержимого и исходного качества JPEG. Автоматическая замена
результата оригиналом в таком случае не выполняется.

Одинаковые имя и дата дают одинаковый путь: существующий результат пропускается,
а с `--overwrite` заменяется. Сопоставления по содержимому пока нет.
Другие форматы, включая HEIC, PNG и RAW, игнорируются. Утилита не заменяет
хранение оригиналов, если важны исходное качество и метаданные.

Запись выполняется через временный файл и переименование в той же папке.
Одновременные запуски этого скрипта в один корень архива блокируются.
Блокировка через `flock` может работать ненадёжно на сетевых файловых системах
(NFS/SMB): не запускайте несколько копий с архивом на таком ресурсе.
Ошибки отдельных файлов выводятся в stderr, остальные файлы продолжают
обрабатываться. Итоговая статистика считает байты только успешно записанных
или скопированных файлов; пропущенные в неё не входят.

Коды завершения: `0` — успешно (в том числе пустая папка/все файлы пропущены),
`1` — ошибка обработки или файловой системы, `2` — неверные параметры.

## Что исправлено и что можно улучшить

Исправлены неполная поддержка EXIF Orientation и неприменённый поворот при
копировании маленьких снимков, отсутствие проверок записи и создания папок,
нулевая сторона при экстремальных пропорциях и некорректные даты EXIF.
Добавлены параметры CLI, статистика, защита от неявной перезаписи,
одновременных запусков и перезаписи исходника.

Возможные следующие шаги, не включённые в текущий алгоритм:

- Рекурсивный обход с сохранением подпапок и явной политикой совпадений имён.
- Манифест с хешами, исходной датой и размерами для поиска дубликатов и проверки архива.
- Сохранение EXIF/ICC через отдельный инструмент и учёт часового пояса EXIF.
- Режим предварительного просмотра и дополнительное правило «сохранять только при экономии места».
- Поддержка HEIC/WebP/AVIF и сравнение качества на реальных фотографиях.

Техническая основа: [официальный PHP Docker image](https://github.com/docker-library/docs/tree/master/php)
и [PHP EXIF](https://www.php.net/manual/en/function.exif-read-data.php).
