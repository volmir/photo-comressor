# Repository Guidelines

## Структура проекта

Проект — пакетный JPEG-компрессор на PHP 8.4 с расширениями GD и EXIF, без Composer и внешних PHP-зависимостей.

- `run.php` содержит CLI, обработку EXIF, масштабирование и запись архива.
- `tests/run.php` — интеграционные проверки; `tests/support.php` — вспомогательные функции EXIF.
- `tests/fixtures/` содержит синтетические JPEG; `scripts/generate-fixtures.php` создаёт отсутствующие изображения.
- `input/` предназначен для оригиналов, `output/` — для результатов в формате `ГОД/ГОД-МЕСЯЦ-ДЕНЬ/имя.jpg`.
- `Dockerfile`, `compose.yaml` и `docker/php.ini` задают окружение; `readme.md` описывает использование.

## Сборка, запуск и проверка

Выполняйте команды из корня репозитория:

```sh
docker compose build
docker compose run --rm compressor
docker compose run --rm compressor --help
docker compose run --rm --entrypoint php compressor /app/tests/run.php
```

Команды соответственно собирают образ, обрабатывают `input/`, показывают параметры и запускают тесты. После изменения PHP-кода пересобирайте образ: исходники копируются при сборке, а не подключаются томом.

Для проверки синтаксиса основного скрипта:

```sh
docker compose run --rm --entrypoint php compressor -l /app/run.php
```

## Стиль кода и именование

Соблюдайте существующий стиль: четыре пробела в PHP, два в YAML, `declare(strict_types=1);`, типизированные параметры и возвращаемые значения. Используйте `camelCase` для функций и переменных, например `processPhoto` и `$inputPath`. Открывающую скобку функции размещайте на отдельной строке; блоков условий — на строке условия. Автоматический форматтер и линтер не настроены. Пользовательскую документацию ведите на русском; сохраняйте английский стиль CLI-сообщений.

## Тестирование

Используется собственный PHP-скрипт с функцией `check()`, без PHPUnit и установленного порога покрытия. Добавляйте проверки в `tests/run.php` с понятными описаниями ожидаемого поведения. Проверяйте изменённые сценарии: ориентацию EXIF, размеры, даты, повторный запуск, ошибки и сохранность оригиналов.

Тесты создают и удаляют временные каталоги. Запускайте их от непривилегированного пользователя контейнера: проверка запрета записи зависит от прав доступа.

## Коммиты и pull request

История использует короткие английские заголовки в повелительном наклонении, например `Add Dockerized PHP photo compressor with fixtures and documentation`; обязательных префиксов нет. Делайте коммиты тематически цельными.

В pull request указывайте проблему, новое поведение, команды проверки и результаты. При изменении обработки изображений приводите исходные и итоговые размеры либо примеры изображений; связывайте задачу, если она существует. Обновляйте `readme.md` при изменении CLI.

## Данные и конфигурация

Не коммитьте личные фотографии, результаты обработки и `.env`. Сохраняйте подключение `input/` только для чтения, явный флаг `--overwrite`, атомарную запись и блокировку архива. Настройки пользователя и памяти передавайте через `LOCAL_UID`, `LOCAL_GID` и `PHP_MEMORY_LIMIT`.
